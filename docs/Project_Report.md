# 股票价格移动方向预测项目报告

## 1. 项目目标与数据概况

本项目基于股票盘口快照数据，预测未来不同 tick 间隔下的中间价移动方向。目标标签包括 `label_5`、`label_10`、`label_20`、`label_40` 和 `label_60`，分别对应未来 5、10、20、40、60 个 tick 的价格方向。每个标签是三分类任务：

| 类别 | 含义 |
|---:|---|
| 0 | 未来价格下跌 |
| 1 | 未来价格基本不变 |
| 2 | 未来价格上涨 |

原始数据共 1521 个 CSV 文件，约 304 万行。每个文件对应一个股票、一个交易日和一个交易时段。主要字段包括时间、股票和日期标识、`n_close`、`n_midprice`、`amount_delta`、五档买卖价、五档买卖量，以及五个预测标签。

EDA 显示数据整体可读性较好：1521 个文件均可读取，没有空文件、重复行、缺失值或 Inf 值。需要注意的是，理论上存在 59 个股票-日期-时段组合缺失；另外，约 1% 左右样本存在买一价高于卖一价等 crossed book 现象，约 5.48% 样本的记录中间价与买一卖一均值存在小幅差异。这些问题没有被直接改写为人工修正值，训练阶段主要通过异常样本过滤和特征清洗降低影响。

## 2. 数据清洗逻辑

数据处理以原始快照文件为单位进行，避免跨股票、跨日期或跨时段引入未来信息。主要清洗流程如下。

1. 文件扫描与排序  
   训练脚本按 `snapshot_sym{sym}_date{date}_{am|pm}.csv` 解析文件名，提取股票、日期和交易时段，然后按日期、上午/下午、股票编号排序。这样切分训练集和验证集时保持时间顺序。

2. 字段类型处理  
   对 `date`、`sym`、`n_close`、`amount_delta`、`n_midprice`、五档买卖价和五档买卖量做数值化转换。无法转换的值记为缺失，后续统一转为 0；正负无穷也会替换为 0。这个步骤保证训练矩阵没有 NaN 或 Inf。

3. 时间顺序整理  
   每个文件内部按 `sym`、`date`、`time` 排序。虽然单个文件通常只包含一个股票和一个交易日，但训练代码仍按 `sym/date` 分组计算滚动特征和滞后特征，保证逻辑一致。

4. 异常盘口过滤  
   默认训练会剔除涨跌停或盘口明显异常样本，规则包括：

   | 条件 | 处理理由 |
   |---|---|
   | `n_ask1 == 0` | 卖一价缺失，盘口不可正常解释 |
   | `n_bid1 == 0` | 买一价缺失，盘口不可正常解释 |
   | `n_close >= 0.095` | 接近涨停，价格行为受交易制度约束 |
   | `n_close <= -0.095` | 接近跌停，价格行为受交易制度约束 |

5. 历史不足样本过滤  
   每个 `sym/date` 分组的前 4 行样本会被跳过。最终特征向量需要最近 5 帧的完整基础特征，前几行历史不足，直接训练会引入大量边界填充值。

6. 标签与收益辅助量处理  
   每个标签使用原始 CSV 中提供的 `label_*`。训练时额外计算 `price_diff_raw = future_n_midprice - current_n_midprice`，用于验证阶段的阈值选择和 PnL 方向检查。标签缺失时填为 1，价格差缺失时填为 0。

7. 训练缓存生成  
   清洗和特征构造后，样本被分批写入 XGBoost 外存缓存。这样可以在展开 922 维特征向量后仍使用全量数据训练，避免一次性加载全部矩阵造成内存压力。

## 3. 特征工程

最终模型使用 182 个基础特征，并将最近状态和远端摘要拼接为 922 维最终向量。特征构造只使用当前 tick 及历史 tick，不使用未来价格。

### 3.1 原始盘口与价格基础特征

基础输入包括 `n_close`、`n_midprice`、`amount_delta`，以及 1 至 5 档买卖价格和买卖量。这些字段保留了盘口的原始结构，是所有衍生因子的基础。

逻辑上，这类特征直接描述当前价格水平、成交活跃度和五档挂单分布。树模型可以从中学习不同价格层级和挂单量之间的非线性关系。

### 3.2 价差、中间价与加权价格

主要特征包括：

- `spread_1`、`spread_3`、`spread_5`
- `mid_price_1`、`mid_price_3`、`mid_price_5`
- `weighted_ab_1`、`weighted_ab_3`
- `micro_price`、`micro_price_diff`

价差反映即时流动性和交易成本。多档中间价、加权盘口价和 micro price 会把价格与挂单量结合起来，用于衡量买卖力量不均衡时的短期价格倾向。

### 3.3 深度、密度与不平衡因子

主要特征包括：

- `relative_bid_density_*`、`relative_ask_density_*`
- `vol1_rel_diff`、`vol3_rel_diff`、`vol5_rel_diff`
- `total_imbalance`、`total_imbalance_weighted`
- `weighted_depth_imbalance`
- `depth_pressure`、`book_curvature`

这类因子刻画买卖盘的相对厚度。买盘更厚通常意味着下方承接更强，卖盘更厚则可能压制上行。多档版本用于区分最优价附近压力和更深层盘口压力。

### 3.4 差分、滞后与滚动统计

主要特征包括：

- `close_delta`、`bid1_delta`、`ask1_delta`、`midprice_delta`
- 各价格和挂单量的 rolling mean、rolling std、相对均值偏离
- `lag_mid_*`、`lag_bid1_*`、`lag_ask1_*`、`lag_bsize1_*`、`lag_asize1_*`
- `midprice_ma5`

高频盘口数据噪声较大，单点水平容易受偶然成交和撤单影响。差分和滞后特征描述短期变化方向，滚动均值和标准差提供局部基准，使模型能判断当前值是正常波动还是偏离状态。

### 3.5 动量、波动和技术指标

主要特征包括：

- `roc_1`、`roc_5`、`roc_10`、`roc_30`、`roc_60`、`roc_100`
- `volatility_5`、`volatility_10`、`volatility_20`、`volatility_40`、`volatility_60`
- `macd_dif`、`macd_dea`、`macd_bar`
- `kdj_k`、`kdj_d`、`kdj_j`
- `price_zscore_*`、`price_slope_*`、`price_percentile_100`

这类特征描述价格短期趋势、局部波动强弱和当前位置。它们对较长 horizon 的标签更有帮助，因为 `label_40`、`label_60` 更依赖一段时间内的价格惯性和波动状态。

### 3.6 成交额与流量因子

主要特征包括：

- `amount_normalized`
- `amount_zscore_*`、`amount_slope_*`
- `volume_flow_5`、`volume_flow_20`、`volume_flow_60`
- `buy_intensity`、`sell_intensity`
- `vpin_5`、`vpin_20`

成交额和成交强度用于衡量市场参与程度。价格变化如果伴随更高成交额，通常比低成交额下的价格跳动更有信息量。VPIN 类特征用于描述成交流量波动，帮助识别短期流动性冲击。

### 3.7 订单流压力因子

主要特征包括：

- `ofi_1`、`ofi_avg_3`
- `ofi_1_rolling_5`
- `ofi_ema_5`、`ofi_ema_10`
- `ofi_spread_ratio`
- `ofi_momentum_sync`
- `orderbook_pressure`

订单流不平衡（OFI）用买卖价和买卖量的连续变化估计主动压力。若 OFI 与价格动量同步，说明盘口变化和价格移动方向一致，信号更可信。

### 3.8 时间与最终拼接方式

时间特征包括 `time_seconds` 和 `time_interval`。前者保留日内连续位置，后者将交易日划分为粗粒度时间段。开盘、午盘和收盘附近的流动性和波动模式不同，时间特征可以帮助模型区分这些状态。

最终向量采用“近期完整信息 + 远端摘要”的拼接结构：

- 最近 5 帧完整基础特征：`t0`、`t1`、`t2`、`t3`、`t4`
- 较远历史摘要：在 5、10、20、40、80、100 tick 的滞后位置提取 `n_midprice` 和 `total_imbalance`

该结构保留近期盘口细节，同时加入更长时间尺度的方向和供需摘要。最终特征维度为 `182 * 5 + 6 * 2 = 922`。

## 4. 模型、参数与训练方式

### 4.1 模型结构

实际训练采用 XGBoost 多分类模型。五个标签分别训练五个模型，推理时同一个 922 维特征向量输入五个模型，输出五个方向预测。

模型目标函数为：

- `objective`: `multi:softprob`
- `num_class`: `3`
- `eval_metric`: `mlogloss`

推理阶段先得到三类概率。如果下跌类或上涨类概率超过对应标签阈值，则输出 0 或 2；如果两侧置信度都不足，则输出 1。该阈值化逻辑用于控制交易信号数量，避免把低置信度样本强行判为方向信号。

### 4.2 训练参数

主线全量模型使用的核心参数如下：

| 参数 | 数值 |
|---|---:|
| `max_depth` | 8 |
| `learning_rate` | 0.05 |
| `subsample` | 0.6 |
| `colsample_bytree` | 0.4 |
| `min_child_weight` | 50 |
| `reg_alpha` | 10.0 |
| `reg_lambda` | 2.0 |
| `gamma` | 0.5 |
| `tree_method` | `hist` |
| `max_bin` | 256 |
| `num_boost_round` | 2000 |
| `early_stopping_rounds` | 100 |
| `batch_size` | 5000 |
| `random_state` | 42 |

训练时根据训练集类别频数计算 class weight，缓解 `Unchanged=1` 类占比偏高的问题。后续还尝试过 profit-weight 版本，即按未来价格变化绝对值对样本加权，但该版本没有成为最终主线。

### 4.3 训练/验证切分

项目中主要使用过两种切分方式：

| 切分方式 | 说明 | 用途 |
|---|---|---|
| 文件顺序 8:2 切分 | 1521 个文件中前 1216 个训练，后 305 个验证 | 早期全量基线和若干阈值实验 |
| 日期切分 | `date < 63` 训练，`date >= 63` 验证；共 1205 个训练文件、316 个验证文件 | 最终主线版本 |

日期切分更符合 out-of-time 验证思路，减少同一日期市场状态同时出现在训练和验证中的风险。最终提交采用日期切分训练出的模型，并使用 turbo 推理路径提升平台运行速度。

### 4.4 最终主线模型训练指标

最终主线模型的训练指标来自模型文件保存的 XGBoost 元数据，`best_score` 为验证集 `mlogloss`。

| 标签 | 阈值 | best_iteration | best_score / eval mlogloss |
|---|---:|---:|---:|
| `label_5` | 0.88 | 913 | 0.815588 |
| `label_10` | 0.82 | 913 | 0.870272 |
| `label_20` | 0.78 | 516 | 0.936214 |
| `label_40` | 0.70 | 341 | 1.005695 |
| `label_60` | 0.65 | 187 | 1.036330 |

短 horizon 的 `mlogloss` 更低，主要因为 `label_5`、`label_10` 中“不变”样本占比较高，模型更容易识别主体类别。较长 horizon 的类别分布更均衡，方向移动更多，分类难度随之上升。

## 5. 各版本结果与分析

本节只概述关键版本的结果。平台指标以提交后返回的 precision、recall、F0.5、total PnL、single PnL 和 model score 为准。本地验证结果主要用于解释模型和阈值行为。

### 5.1 文件顺序切分的全量 XGBoost 基线

该版本使用 1216/305 文件顺序切分，训练样本数约 225 万，验证样本数约 58.3 万。五个标签均完成全量训练，早期保存的默认阈值为 0.88，随后根据验证集调成：

| 标签 | 阈值 | 验证 precision | 验证 recall | 验证 F0.5 |
|---|---:|---:|---:|---:|
| `label_5` | 0.88 | 0.8016 | 0.0516 | 0.2053 |
| `label_10` | 0.82 | 0.7671 | 0.0642 | 0.2404 |
| `label_20` | 0.78 | 0.6325 | 0.0669 | 0.2351 |
| `label_40` | 0.70 | 0.6140 | 0.0430 | 0.1681 |
| `label_60` | 0.65 | 0.5980 | 0.0375 | 0.1500 |

该版本验证集上表现为高 precision、低 recall。短 horizon 精度较高，但信号覆盖较窄。后续平台结果表明，仅依赖验证集高置信度阈值容易造成交易数量不足，泛化到平台数据后 PnL 不稳定。

### 5.2 收益筛选阈值版本

该版本没有重新训练模型，只调整阈值以偏向更高 single PnL，并设置最低约 1% 的信号率约束。三个已完成平台任务结果如下：

| 标签 | precision | recall | F0.5 | total PnL | single PnL |
|---|---:|---:|---:|---:|---:|
| `label_5` | 0.8247 | 0.0353 | 0.1507 | -0.0950 | -0.000019 |
| `label_10` | 0.8288 | 0.0263 | 0.1167 | 2.0224 | 0.000387 |
| `label_20` | 0.7101 | 0.0259 | 0.1130 | 3.5769 | 0.000709 |

该版本的方向 precision 仍然较高，但 recall 明显偏低。`label_20` 有正收益，`label_5` 变为负收益，说明验证集中筛出的高置信度信号不能稳定代表平台上的高收益信号。

### 5.3 高阈值版本

进一步提高分类概率阈值后，平台返回结果如下：

| 标签 | precision | recall | F0.5 | total PnL | single PnL |
|---|---:|---:|---:|---:|---:|
| `label_5` | 0.953488 | 0.000346 | 0.001727 | -0.269940 | -0.006278 |
| `label_10` | 1.000000 | 0.000085 | 0.000425 | -0.111900 | -0.007993 |
| `label_20` | 0.921260 | 0.000845 | 0.004212 | -0.440893 | -0.003472 |
| `label_40` | 0.855491 | 0.000779 | 0.003878 | -0.166795 | -0.000964 |
| `label_60` | 0.822581 | 0.000711 | 0.003542 | 0.123083 | 0.000662 |

该版本验证了一个关键问题：分类概率极高时，方向命中率可以很高，但信号数量过少，F0.5 接近 0，平台收益也容易被少数样本支配。后续版本不再继续单纯提高分类阈值。

### 5.4 Profit-weight 训练版本

Profit-weight 版本在训练阶段对未来价格变化绝对值较大的样本增加权重，尝试让模型更关注可能带来收益的样本。该版本验证集上信号数增加，长 horizon 的 recall 有所改善，但 precision 明显下降：

| 标签 | 阈值 | 验证 precision | 验证 recall | 验证 F0.5 |
|---|---:|---:|---:|---:|
| `label_5` | 0.94 | 0.4880 | 0.0330 | 0.1299 |
| `label_10` | 0.90 | 0.5660 | 0.0480 | 0.1792 |
| `label_20` | 0.85 | 0.4780 | 0.0720 | 0.2246 |
| `label_40` | 0.75 | 0.4990 | 0.0660 | 0.2158 |
| `label_60` | 0.70 | 0.5090 | 0.0590 | 0.2016 |

该实验说明，按价格变化幅度加权可以改变信号分布，但会牺牲方向分类质量。由于平台最终评分同时受 F0.5 和收益影响，单独提高大波动样本权重并不稳定。

### 5.5 `label_20` 单模型复现实验

为追踪 `label_20` 的历史表现，项目单独训练并评估过 `label_20` 模型。两个代表阈值结果如下：

| 实验 | 阈值 | precision | recall | F0.5 |
|---|---:|---:|---:|---:|
| 早期参数单模型 | 0.82 | 0.6611 | 0.0461 | 0.1803 |
| 早期参数单模型 | 0.88 | 0.7273 | 0.0164 | 0.0753 |
| 主线特征单模型 | 0.82 | 0.6700 | 0.0396 | 0.1601 |
| 主线特征单模型 | 0.88 | 0.7348 | 0.0129 | 0.0603 |

该结果体现出典型阈值权衡：阈值提高后 precision 上升，但 recall 和 F0.5 快速下降。`label_20` 在中等阈值附近能获得相对平衡的 recall，但 precision 达不到高阈值水平。

### 5.6 日期切分 + turbo 推理最终版本

最终提交版本采用 `date >= 63` 的 out-of-time 验证切分训练，提交包使用 turbo 推理路径。turbo 路径只优化推理速度，不改变模型文件和阈值；本地 256 窗口检查与原始推理路径没有预测差异。

平台返回结果如下：

| 标签 | precision | recall | F0.5 | total PnL | single PnL | model score |
|---|---:|---:|---:|---:|---:|---:|
| `label_5` | 0.801436 | 0.051800 | 0.205793 | -0.415608 | -0.000054 | -0.000425 |
| `label_10` | 0.762540 | 0.065955 | 0.245007 | 2.097210 | 0.000147 | -0.000156 |
| `label_20` | 0.623320 | 0.069378 | 0.240026 | 11.716000 | 0.000761 | 0.000312 |
| `label_40` | 0.591949 | 0.041230 | 0.161229 | 14.614600 | 0.001104 | 0.000798 |
| `label_60` | 0.581890 | 0.028868 | 0.120440 | 12.589500 | 0.001179 | 0.000731 |

这个版本是目前最稳定的提交版本。`label_20`、`label_40`、`label_60` 均获得正 model score，其中 `label_40` 分数最高，`label_60` 的 single PnL 较高。`label_5` 和 `label_10` 仍然保持较高 precision，但 single PnL 低于平台基准，导致 model score 为负。

整体看，短 horizon 的方向分类更容易，但价格移动幅度小，扣除评分基准后收益不足；长 horizon 的方向分类更难，但一旦命中，收益空间更大。因此后续优化重点应放在 `label_20`、`label_40`、`label_60`，并对短 horizon 使用更严格的收益筛选或直接降低权重。

## 6. 结果分析

1. 分类精度与收益质量不完全一致  
   高 precision 不能保证高 PnL。高阈值版本在平台上 precision 很高，但 recall 极低，F0.5 和收益都不理想。这说明 XGBoost 的方向类别概率不能直接等同于预期收益。

2. 阈值策略对结果影响很大  
   同一组模型在不同阈值下会得到完全不同的信号覆盖。阈值过低会增加错误方向，阈值过高会失去覆盖率。当前较合理的策略是按标签分别设阈值，短 horizon 使用高阈值，长 horizon 使用相对低阈值。

3. 日期切分优于文件顺序切分  
   文件顺序切分可用于快速复现和调参，但可能让同一日期的市场状态分布进入训练和验证两侧。日期切分更接近真实 out-of-time 预测，最终平台结果也比高阈值版本更稳。

4. 长 horizon 更适合收益目标  
   `label_40` 和 `label_60` 的 precision 低于短 horizon，但平台 single PnL 明显更好，最终 model score 为正。方向难度和收益空间之间存在权衡，不能只按 precision 排序。

5. Profit-weight 需要更精细的目标设计  
   简单按未来绝对价格变化加权会放大大波动样本，但没有区分模型是否能稳定判断方向。更合理的方向是直接建模有符号收益或交易期望值。

## 7. 后续可尝试方向

1. 直接预测预期收益  
   在三分类方向模型之外，增加回归模型或二阶段模型预测 signed return / expected PnL。第一阶段判断是否有方向，第二阶段判断该方向是否有足够收益空间。

2. 分标签优化目标  
   `label_5`、`label_10` 更适合严格筛选，避免低收益信号进入提交；`label_20`、`label_40`、`label_60` 可尝试更高覆盖率的正期望策略。

3. 多验证切片阈值校准  
   目前阈值主要来自单一验证切分。后续可以按日期段、股票、上午/下午分别评估阈值稳定性，并要求每个阈值在多个切片上都保持正向表现。

4. 概率校准与排序模型  
   对 XGBoost 输出概率做 calibration，或训练专门的排序模型区分高收益交易机会。这样比直接使用分类概率阈值更贴近平台评分目标。

5. 模型集成  
   可以尝试多个日期切分、多个随机种子、不同 max_depth / regularization 的模型集成。集成的目标是降低单模型在平台数据上的方差，而不是单纯提高本地验证指标。

6. 特征选择和 horizon 专属特征  
   当前五个标签共用同一套特征。后续可以为短 horizon 强化订单流和最优价变化特征，为长 horizon 强化趋势、波动和成交流量特征。

7. 数据质量再审查  
   对 crossed book、midprice mismatch 和涨跌停样本做更细粒度分析。只有在确认修正规则与标签生成逻辑一致时，才应重算价格字段；否则保留原始字段并用异常标记或过滤处理更稳妥。

8. 提交层面稳健性检查  
   每次提交前固定执行包结构检查、导入路径检查、批量推理 smoke test、原始/加速推理 parity check 和运行时间 benchmark，避免工程问题影响模型结果。
